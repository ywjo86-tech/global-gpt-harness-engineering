### SOURCE ID-01

## Purpose

본 구현설계는 승인된 `PREPH5MPRF_APPROVED_DEVELOPMENT_PLAN.md`를 유일한 Planning Authority로 사용하여, Full MCP PHASE 4 승인 baseline 위에서 PCA-001, EXEC-AUTH-EXT-001/PCA-002, MPRF-001을 하나의 통합 프로그램으로 구현하기 위한 구체적 HOW를 정의한다. 실제 코드 변경, test 실행, provider worker 실행, Git mutation 또는 baseline 선언은 수행하지 않는다.

## Design Goal

핵심 설계 목표는 네 가지다. 첫째, GPT를 Full Plan Operator로 유지하면서 Provider Router가 Provider/Model 선택 권한을 독점하도록 현재 HYBRID runtime을 보완한다. 둘째, Provider Router 계약을 MPRF consumer가 필요한 eligibility/failure/failover 입력까지 versioned public contract로 확장한다. 셋째, Full MCP의 closed action authority에 `git_stage`, `git_commit`, `git_push`를 안전한 publication pipeline으로 추가하되 canonical action effect truth와 승인 경계를 보존한다. 넷째, MPRF를 Provider Runtime Foundation으로만 신설하여 registry/lifecycle/health/quota/failover/checkpoint/telemetry를 제공하되 Router 선택 권한과 Full MCP action authority를 흡수하지 않는다.

## Expected Implementation Outcome

구현과 검증이 완료되면 `PCA-001 PASS + EXEC-AUTH-EXT-001 PASS + PCA-002 CLOSED + MCP_STABLE_BASELINE RECONFIRMED`가 먼저 성립하고, 그 후에만 MPRF Foundation이 활성화된다. 최종적으로 Router authority, Full MCP action/effect authority, failure/recovery order, observability source-of-truth separation, security negative space, integrated E2E가 모두 PASS해야 `MULTI_PROVIDER_FOUNDATION_BASELINE` 선언 가능 상태가 된다.

현재 설계 시점의 중요한 상태는 `RUNTIME_POLICY_MISMATCH`다. 기존 runtime은 HYBRID에서 read-only를 NVIDIA, state-changing을 Codex로 라우팅하지만, 승인 정책이 요구하는 GPT Operator control contract, NVIDIA prepare → Codex action의 explicit planned handoff, Router-owned model binding, Codex unavailable 시 GPT-authorized Manual Action 또는 operator-visible queue/block를 완전하게 표현하지 않는다. 이 불일치는 계획 범위 내 bounded prerequisite remediation인 TASK-017로 설계하며, GATE-001은 TASK-017 검증 전까지 실행 NO_GO다.

## Current Limitations / Runtime Compatibility Findings

- **RTMISMATCH-001 — GPT Operator control path absent as an explicit runtime contract.** Current engine controls sequencing internally; no versioned GPT operator directive/acknowledgement boundary was found.

## Component Details

### CMP-D-001 — Operator Control

Responsibility: expose a versioned, provider-neutral `OperatorDirective` that permits GPT to advance a task through PREPARE, ACTION, VERIFY, REVIEW and GATE_DECISION states.  
Inputs: project/run/task IDs, current stage, requested capability set, `state_change_required`, prior artifact digest, gate context.  
Outputs: validated transition token/record; no provider identity.  
Dependencies: CMP-D-002 Router, CMP-D-004 queue/state.  
State Behavior: transition is monotonic and lineage-bound; ACTION cannot exist without an accepted PREPARE artifact when state-changing work needs generated patch/action material.  
Error Behavior: stale/mismatched directive is blocked; no implicit provider call.  
Compatibility: current one-shot tasks can be represented as PREPARE-only when no state change is required.  
Preserved Behavior: stage-gate authority remains outside provider adapters.

### CMP-D-002 — Provider Router v2

Responsibility: sole provider/model selection and reroute decision authority.  
Inputs: versioned `RouterRequest` with stage, capabilities, state-change flag, provider/model eligibility snapshot, failure/failover context, policy profile.  
Outputs: `RouterDecision` with provider_ref, model_ref, reason_code, eligibility evidence refs, decision digest.  
Dependencies: MPRF eligibility evidence when available; static approved policy profile during pre-MPRF remediation.  
State Behavior: deterministic policy, no scoring/benchmarking.  
Error Behavior: no eligible provider/model → `ROUTE_BLOCKED`, never silent fallback.  
Compatibility: v1 compatibility adapter accepts old mode/capability calls but produces v2 decision; old consumers remain test-covered.  
Preserved Behavior: only Router selects provider/model.

### CMP-D-003 — Provider Executor / Handoff

Responsibility: execute exactly the provider/model chosen by Router for the current stage and seal result/handoff.  
Inputs: RouterDecision + task stage package.  
Outputs: normalized provider result and `ProviderHandoffPackage` digest.  
Dependencies: provider adapters.  
State Behavior: PREPARE result may create ACTION package; ACTION result may create VERIFY package. Each stage has new execution identity; a failed PREPARE is not converted into ACTION.  
Error Behavior: provider failure returns classified result to GPT/MPRF; no provider reselection inside executor.  
Compatibility: existing result normalization retained with versioned `provider_trace` extension.  
Preserved Behavior: adapter-specific transport remains behind provider executor.

### CMP-D-004 — Task Queue / Runtime State

Responsibility: persist task/stage status and deterministic fan-in readiness.  
New states: `PREPARE_PENDING`, `PREPARE_RUNNING`, `PREPARED`, `ACTION_PENDING`, `ACTION_PROVIDER_BLOCKED`, `ACTION_RUNNING`, `ACTION_RECONCILE`, `ACTION_COMPLETED`, `VERIFY_PENDING`, `VERIFIED`, `RECOVERY_REQUIRED`, plus existing approval/gate states.  
Error Behavior: Codex unavailable/quota routes the state-changing boundary to GPT Operator. An exact bounded Manual Action may be authorized; otherwise set `ACTION_PROVIDER_BLOCKED/QUEUED`. It never marks success or switches provider automatically.  
Compatibility: existing pending/completed/failed projections remain derivable.

### CMP-D-005 — NVIDIA Adapter

Responsibility: read-only work execution only.  
Change: `model_ref` becomes mandatory from RouterDecision for governed HYBRID execution; environment model may remain only in standalone legacy mode, not authoritative HYBRID mode.  
Error Behavior: failure taxonomy is returned without calling Codex.  
Preserved Behavior: context sanitizer, retries for allowed transient NVIDIA call attempts, no state-changing tools.

### CMP-D-006 — Codex Adapter / Launcher

Responsibility: state-changing action provider boundary.  
Change: accept Router-bound provider/model/action package and return explicit availability/failure taxonomy; when Codex is unavailable, emit a GPT-reviewable exact Manual Action package that cannot execute or advance without explicit GPT Operator authorization.  
Error Behavior: CLI unavailable/auth/quota/transport failure cannot advance action state.  
Security: action package is immutable/digest-bound before launch.

### CMP-D-007 — Public Execution Contract

Responsibility: PCA-002 consumer API between MPRF and Execution Backend/Full MCP.  
Inputs: `PublicExecutionRequest` containing action class, authorization ref, operation request ID, correlation IDs, public arguments schema, effect reconciliation ref.  
Outputs: `PublicExecutionResult`, `PublicExecutionStatus`, `PublicReconciliationResult`.  
Forbidden: ToolEffectJournal, internal receipt store, internal operation registry, internal Full MCP class handles or file paths.  
Implementation location is orchestrator/public contract namespace, not `runtime/mprf` and not private Full MCP modules.

### CMP-D-008 — Full MCP Contracts/Auth

Responsibility: preserve exact authorization and add publication-specific policy binding.  
Design: retain InvocationContext v1 for existing operations; introduce backward-compatible `gch.full-mcp.invocation-context.v2` with `operation_policy_digests`. Publication operations require v2 and a matching `GitPublicationAuthorization.v1` digest. Existing operations remain valid under v1/v2 compatibility rules.  
Security: repository identity, branch, remote, expected remote head, allowed path digest, approval ref and validity window are sealed in the publication authorization record.

### CMP-D-009 — Full MCP Git Service

Responsibility: implement publication primitives without shell passthrough.  
`stage`: exact approved pathspecs only; verify worktree scope/unrelated changes; compute candidate diff + pre/post index digests.

## Interface Details

### IF-001 — OperatorDirective.v1

Required fields: `schema_version`, `project_id`, `run_id`, `task_id`, `task_execution_id`, `current_stage`, `requested_next_stage`, `required_capabilities`, `state_change_required`, `input_artifact_digests`, `gate_id`, `directive_id`.  
Contract: directive cannot include `provider` or `model`; those fields are rejected.  
Error Handling: stale stage, missing predecessor digest or forbidden transition → `OPERATOR_DIRECTIVE_BLOCKED`.  
Security: directive digest is included in RouterRequest and stage evidence.

### IF-002 — RouterRequest.v2

Required fields: identity/correlation, stage, canonical capabilities, `state_change_required`, policy profile, eligibility snapshot ref/digest, optional failure class and failover request ref.  
Contract: Router alone interprets policy profile and eligibility to select provider/model.  
Compatibility: v1 `mode + capabilities` is normalized into v2 with explicit legacy source and no MPRF failure context.  
Error Handling: unsupported schema/policy/eligibility digest mismatch → blocked decision.

### IF-003 — RouterDecision.v2

Fields: `decision_id`, `request_digest`, `provider_ref`, `model_ref`, `reason_code`, `required_capabilities`, `eligible`, `eligibility_evidence_refs`, `policy_version`, `decision_digest`.  
Rule: provider/model refs are mandatory for governed HYBRID execution; adapters cannot substitute them.  
Negative space: no cost score, benchmark score, dynamic provider discovery or automatic fallback chain.

### IF-004 — ProviderHandoffPackage.v1

Fields: parent execution ID, stage, provider decision digest, input/output artifact digests, proposed change manifest, required next capabilities, `state_change_required`, warnings/errors, immutable handoff digest.  
ACTION handoff rule: only a completed PREPARE package can request ACTION; failure packages request diagnosis/reroute, not action escalation.  
VERIFY handoff rule: references action result/effect evidence, never copies canonical effect truth.

### IF-005 / IF-006 — Public Execution Contract

Public request contains only operation class, public arguments, authorization/policy refs, correlation IDs and expected effect semantics. Public result projects `status`, `result_digest`, `effect_ref`, `reconciliation_state`, `error_code`, `audit_ref`.  
Forbidden public fields: internal Python class names, journal path, receipt store path, internal registry handles, raw authorization secrets.

### IF-007 — GitPublicationAuthorization.v1

Fields: project/repository identity digest, approved branch, approved remote name + URL fingerprint, allowed path digest, expected remote head, protected-branch policy ref, approval ref, issue/expiry timestamps, operation set (`stage`,`commit`,`push`), policy digest.  
Binding: digest must appear in InvocationContext v2 `operation_policy_digests`; each publication call references the exact digest.  
Freshness: push preflight compares actual remote head with authorized/last reconciled head.

### IF-008 — GitStageIntent.v1

Fields: path list, expected worktree digest, expected HEAD, candidate diff digest, publication policy digest.  
Output: staged path list, index digest before/after, staged diff digest.  
Fail closed: unrelated modified/untracked paths outside allowed scope do not get silently staged; if policy requires a clean unrelated scope, they block.

### IF-009 — GitCommitIntent.v1

Fields: expected staged diff digest/index digest, expected HEAD/parent, bounded subject, publication policy digest.  
Output: commit SHA, tree SHA, parent SHA, committed diff digest.  
Guard: any extra staged change or index drift blocks commit.

### IF-010 — GitPushIntent.v1

Fields: remote, branch, local commit SHA, expected remote head, publication policy digest.  
Output: pre/post remote head, push status, remote reconciliation evidence.  
Prohibitions: no force flags, no refspec outside approved branch, no delete, no tag publication unless separately authorized (not in this program).

### IF-011 — ProviderEligibilitySnapshot.v1

Fields: snapshot version/id/digest, provider records, model records, capability availability, health class, quota class, rate-limit class, admission state, observed-at timestamp.  
Rule: snapshot supplies facts; Router produces selection.

### IF-012 — RerouteRequest.v1

Fields: original Router decision, failure class, checkpoint/artifact/effect/auth validation refs, failover policy version, requested capabilities.  
`failure_class` is a closed `FailureClass.v1` enum with exactly: `TASK_FAILURE`, `MODEL_FAILURE`, `PROVIDER_FAILURE`, `AUTH_FAILURE`, `RATE_LIMIT`, `QUOTA_EXHAUSTION`, `NETWORK_FAILURE`, `INVALID_RESPONSE`, `POLICY_REJECTION`, `CHECKPOINT_FAILURE`, `EXECUTION_BACKEND_FAILURE`, `ACTION_SIDE_EFFECT_AMBIGUOUS`, `RECOVERY_REQUIRED`, `UNKNOWN_FAILURE`. Unknown values fail schema validation rather than being coerced.  
Eligible reroute classes are only `MODEL_FAILURE`, `PROVIDER_FAILURE`, `RATE_LIMIT`, `QUOTA_EXHAUSTION`, and `NETWORK_FAILURE` when versioned policy explicitly classifies that network case as safe. `TASK_FAILURE` requires underlying-cause classification first. `INVALID_RESPONSE` is not eligible by this baseline. `AUTH_FAILURE` is prohibited when permission-related; `POLICY_REJECTION`, `CHECKPOINT_FAILURE` until recovery, `EXECUTION_BACKEND_FAILURE`, `ACTION_SIDE_EFFECT_AMBIGUOUS`, `RECOVERY_REQUIRED`, and unresolved `UNKNOWN_FAILURE` cannot request failover.  
Every accepted RerouteRequest therefore carries one exact enum value plus evidence that the ID-09 failure-disposition matrix prerequisites were completed.

### IF-013 — MPRFCheckpoint.v1

Fields: project/run/task/stage lineage, provider runtime state version, artifact digest refs, Router decision refs, public action effect/reconciliation refs, authorization ref, integrity digest.  
No raw action receipt/effect journal data is stored.

### IF-014 / IF-015 — Event and Correlation

ProviderRuntimeEvent owns provider/model lifecycle facts. Full MCP action events own execution/effect facts. Shared identifiers are `project_id`, `project_run_id`, `task_id`, `task_execution_id`, `correlation_id`, `operation_request_id`; shared IDs do not grant cross-domain update authority.

## Authoritative Source Projection — ID-09 Data / Control / State Flow

## 9.1 Full Plan Control Flow

1. GPT Operator reads current Gate/task state and issues an `OperatorDirective` for PREPARE/REVIEW/VERIFY or ACTION.
2. Operator Control validates dependency/gate/stage lineage and emits a provider-neutral RouterRequest.
3. Provider Router consumes approved policy plus MPRF eligibility snapshot (or pre-MPRF static compatibility snapshot) and selects provider+model.
4. Provider Executor invokes exactly that decision.
5. PREPARE/REVIEW/VERIFY results are sealed as a handoff package and returned to GPT Operator.
6. If PREPARE completed and state change is required, GPT may authorize a distinct ACTION stage; Router then selects the action provider/model under the same policy authority.
7. ACTION goes through Public Execution Contract / Full MCP controlled boundary. Result/effect references return to GPT Operator.
8. GPT requests VERIFY, normally a read-only capability stage. Router selects per policy.
9. GPT uses evidence to make Gate decision. Provider adapters do not make Gate decisions.

## 9.2 Planned Handoff vs Fallback

```text
PLANNED HANDOFF
PREPARE_COMPLETED
  → immutable handoff digest
  → GPT directive: ACTION
  → fresh RouterRequest(stage=ACTION)
  → fresh RouterDecision
  → ACTION execution

PROHIBITED FALLBACK
NVIDIA PREPARE FAILURE
  ↛ automatically invoke Codex on same task/stage
```

A failed PREPARE is classified. Eligible provider/model failures may later generate a Router reroute request for the same **read-only PREPARE stage** after checkpoint/policy validation; that is distinct from changing the stage to ACTION.

## 9.3 Provider-Unavailable Flow

```text
ACTION_PENDING
  ↓ Router selects eligible action provider
provider unavailable / quota / auth readiness failure
  ↓
ACTION_PROVIDER_BLOCKED
  ├─ independent NVIDIA-safe tasks may continue
  └─ no mutation / no gate advancement
      ↓ when eligibility changes and GPT reissues directive
fresh RouterRequest → ACTION retry attempt with new attempt lineage
```

## 9.5 Failure Taxonomy / Failover Disposition

`FailureClass.v1` is closed and versioned. The implementation must preserve the following exact baseline mapping; a class may not gain failover eligibility by inference, adapter behavior, retry convenience, or provider availability.

| Failure Class | Failover Eligibility | Required Primary Handling | RerouteRequest.v1 Rule |
|---|---|---|---|
| `TASK_FAILURE` | Not eligible by this class alone | Classify the underlying cause; fail closed until an eligible class is established | PROHIBITED until reclassified to an exact eligible cause |
| `MODEL_FAILURE` | Eligible | Complete checkpoint/artifact/effect/auth/policy checks | MAY request Router reroute after all prerequisites |
| `PROVIDER_FAILURE` | Eligible | Complete checkpoint/artifact/effect/auth/policy checks | MAY request Router reroute after all prerequisites |
| `AUTH_FAILURE` | Permission-related: prohibited | Correct/revalidate authorization; no authority expansion | PROHIBITED for permission-related failure |
| `RATE_LIMIT` | Eligible | Apply versioned failover/reroute policy after integrity checks | MAY request Router reroute after all prerequisites |
| `QUOTA_EXHAUSTION` | Eligible | Apply versioned failover/reroute policy after integrity checks | MAY request Router reroute after all prerequisites |
| `NETWORK_FAILURE` | Eligible only when policy classifies the case as safe | Validate checkpoint/integrity/effect state first | MAY request Router reroute only with safe-policy evidence |
| `INVALID_RESPONSE` | Not eligible by this baseline | Validate response and classify/remediate without provider failover | PROHIBITED unless a future controlled policy revision changes baseline |
| `POLICY_REJECTION` | Prohibited | Governance/policy resolution | PROHIBITED |
| `CHECKPOINT_FAILURE` | Prohibited until recovery | Repair/re-establish checkpoint integrity; enter recovery as required | PROHIBITED until recovery completes and a new eligible failure exists |
| `EXECUTION_BACKEND_FAILURE` | Prohibited | Recover backend while preserving canonical action truth | PROHIBITED |
| `ACTION_SIDE_EFFECT_AMBIGUOUS` | Prohibited | Reconcile canonical effect/remote state; no automatic replay | PROHIBITED |
| `RECOVERY_REQUIRED` | Prohibited | Complete explicit recovery workflow | PROHIBITED |
| `UNKNOWN_FAILURE` | Fail closed | Establish an exact class before any reroute decision | PROHIBITED while unresolved |

Legacy lock remains absolute: `NVIDIA Failure → Codex same-task automatic fallback = PROHIBITED`. An eligible failure may create only a fresh Router-owned reroute request for the same logical stage after the ordered recovery prerequisites; it never authorizes an implicit provider switch or ACTION-stage escalation.

## Regression Requirements

- Full MCP regression must cover existing filesystem, shell, git-read/restore/prepare-commit, validation, auth/effect journal, adapter/gateway and security behavior outside the new publication authority.
- Router regression must prove v1-compatible consumers remain supported under the documented version policy and that provider/model selection authority is not duplicated.
- Runtime compatibility regression must prove GPT stage control, planned handoff and blocked ACTION semantics without introducing same-stage automatic fallback.
- MPRF regression must prove no internal Full MCP coupling, no routing authority, no action authority and no duplicate observability ownership.
- Any remediation after a failed Gate reruns focused tests, dependent regression, independent review and the same Gate.

## Manual Verification

Required only for evidence that cannot be safely asserted by automated tests, such as explicit approval-reference validity, protected-branch policy source, external remote state, and final user authorization. Manual verification must produce a referenced artifact; verbal/unrecorded confirmation is insufficient.

## Security Constraints to Preserve

- Force push, history rewrite, destructive reset, protected-branch bypass and unapproved repo/branch/remote expansion are not implemented as allowed publication operations.
- Existing secret-safe Full MCP observability restrictions remain; MPRF Provider Runtime Events cannot persist action payload/stdout/stderr/credentials.
- Authorization validity is rechecked at resume/retry boundaries; checkpoint possession is not authorization.
- Provider failure does not grant permission escalation or provider-policy bypass.
- Full MCP closed registry remains the only action operation authority.

## Prohibited Security Changes

- Adding generic git/shell escape hatches for publication.
- Allowing MPRF to write Full MCP journals/receipts or decide action effect state.
- Treating correlation identifiers as authorization tokens.
- Converting an ambiguous push to success or replay without reconciliation.
- Converting policy/permission denial to a routable provider failure.
