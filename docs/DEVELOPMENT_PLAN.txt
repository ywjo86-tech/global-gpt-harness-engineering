## Current Architecture Summary

Read-only verification of the active local worktree on 2026-09-13 confirmed the following relevant flow:

`Development Plan / Execution Contract`  
→ `task_router.py` creates `TaskSlice` by Agent/Task responsibility  
→ `engine.py` packages fan-out work  
→ execution mode dispatch (`mock`, `manual`, `codex-cli`)  
→ local worker or `codex_adapter.py`  
→ `result_normalizer.py`  
→ `result_collector.py`  
→ `fanin.py`  
→ `stage_gate.py`

The active source also contains a separate production execution subsystem and a canonical LV worker contract (`orchestration.lv_worker.result.v1`). This design does not replace or generalize that production subsystem. The Multi-Provider bootstrap is scoped to the existing Full Plan Orchestration worker flow described above.

## Approved Constraints

### Technical

- Existing Orchestrator Runtime and Result Normalizer must be reused.
- Existing Task Router remains Agent/Task router; Provider routing is separate.
- NVIDIA is remote read-only reasoning backend only.
- No dynamic/AI router.

### Compatibility

- Preserve `mock`, `manual`, `codex-cli`.
- Preserve Codex manual fallback semantics.
- Fan-in / Stage Gate must not gain Provider-specific processing branches.

### Security

- NVIDIA is treated as an external hosted provider.
- Secrets/credentials/environment credential values must never be transmitted.
- Source/document transmission is allowed only after approved filtering, bounded task relevance, and forbidden-path enforcement.

### Operational

- NVIDIA failure must not crash the entire runtime.
- Retry is bounded.
- Automatic NVIDIA→Codex fallback must not recreate unconditional Codex concentration.

### Business / Cost

- Phase 1 exists to reduce Codex usage concentration.
- Stop provider expansion after minimum hybrid proof is achieved.

## Approved Success Criteria

- SC-001: Legacy Codex-only and `mock`, `manual`, `codex-cli` behavior remains.
- SC-002: At least one NVIDIA Hosted API read-only reasoning task succeeds.
- SC-003: Codex/NVIDIA normalize to the same worker result flow; fan-in/gate remain provider-agnostic.
- SC-004: deterministic Provider Router selects expected providers and exposes rationale.
- SC-005: at least one Hybrid E2E has NVIDIA reasoning + Codex state-changing execution.
- SC-006: NVIDIA timeout/auth/rate-limit/invalid response/other provider failures do not become uncaught runtime crashes.
- SC-007: API key/secrets/credentials/forbidden context are absent from NVIDIA prompt/result/general logs.
- SC-008: approved baseline regression has no functional damage.
- SC-009: Codex + NVIDIA + Hybrid + Result Contract + Regression success triggers STOP and Full Plan resume.

## Approved Deliverables

- DEL-001: Full Plan Freeze Baseline Record and recovery reference

# ID-06 Architecture Design

## Current Architecture Boundary

In-scope legacy worker execution boundary:

`ExecutionContract`  
→ `Task Router`  
→ `TaskSlice`  
→ `Engine execution mode dispatch`  
→ `{Local Worker | Codex Adapter | Manual}`  
→ `Worker Result Normalizer`  
→ `Result Collector`  
→ `Fan-in`  
→ `Stage Gate`

Preserved separate boundary:

`production_*` modules + canonical LV execution package/result contract.

## Target Architecture

`ExecutionContract`  
→ `Task Router` **(Agent selection + explicit required_capabilities only)**  
→ `TaskSlice` **(+ required_capabilities, input_files)**  
→ `Execution Mode Policy` (`mock/manual/codex-cli/nvidia/hybrid`)  
→ **Provider Router** (`ProviderRouteDecision`)  
→ **Provider Executor**  
→ `{Codex Adapter | NVIDIA Adapter | legacy manual/local worker}`  
→ `Worker Result Normalizer v1 + optional provider metadata`  
→ unchanged `Result Collector`  
→ unchanged `Fan-in`  
→ unchanged/provider-agnostic `Stage Gate`

NVIDIA path only:

`Task prompt + explicit input_files`  
→ **Context Sanitizer**  
→ bounded sanitized context  
→ NVIDIA OpenAI-compatible `POST /v1/chat/completions`  
→ envelope validation  
→ normalized worker result  
→ existing result file/handoff artifacts.

## Preserved Architecture

- Existing Planner/Task Router ownership of Agent/Task selection.
- Existing Codex adapter and Codex→manual fallback semantics.
- Existing local mock worker execution.
- Existing manual task generation.
- Existing `orchestration.worker.result.v1` schema identity.
- Existing Result Collector and Fan-in interpretation of completion/failure.
- Existing Stage Gate semantics.
- Existing production/canonical execution subsystem.

## Changed Architecture

- Execution modes extend with `nvidia` and `hybrid`.
- `TaskSlice` gains backward-compatible capability/context fields.
- Engine gains provider routing/dispatch only for the two new modes.
- Result normalizer preserves optional provider trace metadata.
- External-context security boundary is introduced before NVIDIA transport.

## New Architecture Elements

- `provider_router.py`
- `provider_executor.py`
- `context_sanitizer.py`
- `nvidia_adapter.py`

## Component Details

### CMP-005 — Provider Router

Responsibility: Pure routing decision without network, file mutation, subprocess execution, or model selection logic.

Inputs:
- normalized execution mode
- `TaskSlice.required_capabilities`
- task/thread/agent identity for trace only

Outputs:
- `ProviderRouteDecision(provider, route_reason, allowed, required_capabilities)`

Rules:
- `codex-cli` → existing Codex path, no new router behavior required.
- `mock` / `manual` → existing paths.
- `nvidia` + safe read-only reasoning → NVIDIA.
- `nvidia` + state-changing/unknown → route rejection.
- `hybrid` + safe read-only reasoning → NVIDIA.
- `hybrid` + state-changing/unknown → Codex.

Error Behavior: Invalid mode/capability value fails closed; no NVIDIA dispatch.

Compatibility: Absent `required_capabilities` on legacy serialized TaskSlice becomes empty list and therefore safe-defaults away from NVIDIA.

### CMP-006 — Context Sanitizer

Responsibility: Produce the only payload eligible for external Provider transmission.

Inputs:
- task-specific worker prompt text
- explicit `input_files`
- project root
- configured byte/file limits

Outputs:
- sanitized text context
- safe audit metadata: included file paths, byte counts, redaction count, rejection class

Path policy:
- no recursive repository scan
- resolve every file under project root
- reject symlinks and path escape
- deny `.env`, `.env.*`, `.git/**`, credential/secret/private-key/certificate-key material and equivalent forbidden path classes

Content policy:
- redact values associated with `API_KEY`, `PASSWORD`, `TOKEN`, `SECRET`, `PRIVATE_KEY`, `SSH_KEY`, `AUTHORIZATION`, `CREDENTIAL`
- redact bearer tokens and PEM/private-key blocks
- post-scan sanitized output for unresolved secret patterns
- unresolved sensitive pattern → `context_security_rejected` before network call

Bound policy:
- max 8 explicit input files
- max 16 KiB decoded UTF-8 text per file
- max 64 KiB total sanitized context
- oversize file/content is deterministically truncated with a non-secret truncation marker; context exceeding total limit after assembly is rejected rather than silently exceeding the policy

### CMP-007 — NVIDIA Adapter

Responsibility: Execute one sanitized reasoning request and return a safe provider result.

Runtime configuration:
- `NVIDIA_API_KEY`: required, no default
- `NVIDIA_ENDPOINT`: default `https://integrate.api.nvidia.com/v1`
- `NVIDIA_MODEL`: required, no compiled default
- `NVIDIA_TIMEOUT_SECONDS`: default `30`
- `NVIDIA_MAX_RETRIES`: default `2`
- `NVIDIA_RETRY_BACKOFF_SECONDS`: default `1`
- `NVIDIA_MAX_TOKENS`: default `2048`

Transport:
- HTTPS endpoint derived as `<NVIDIA_ENDPOINT.rstrip('/')>/chat/completions`
- `Authorization: Bearer <NVIDIA_API_KEY>` exists only in request memory
- JSON body includes configured model, non-streaming messages, bounded context and max token limit
- no tool-calling, shell, filesystem, git or test capability

Response contract:
- HTTP 2xx
- JSON object
- non-empty `choices[0].message.content`
- content is treated as worker summary; model is not required to emit executable actions or a secondary JSON schema

Error classes:
- `nvidia_config_error`
- `nvidia_auth_error`
- `nvidia_rate_limit`
- `nvidia_timeout`
- `nvidia_network_error`
- `nvidia_server_error`
- `nvidia_client_error`
- `nvidia_invalid_response`
- `context_security_rejected`

Retry:
- retry: timeout/network/408/429/5xx
- no retry: missing key/model, 401/403, other 4xx, invalid response, sanitizer rejection
- maximum attempts = 1 initial + configured `NVIDIA_MAX_RETRIES`

### CMP-008 — Provider Executor

Responsibility: Convert route decision into backend execution without exposing Provider branches to Fan-in/Gate.

NVIDIA success:
- write normalized `result.json`
- write normal worker `handoff_report.md` / compatibility handoff if required
- include `provider=nvidia`, configured model, route reason, attempt count, status

NVIDIA terminal failure:
- write normalized result with `status=provider_failed`
- include safe error class/attempt count
- do not call Codex automatically
- return control to engine; independent remaining tasks may continue

Codex route:
- call existing `codex_adapter.run_task_prompt` unchanged
- preserve existing Codex→manual fallback
- normalize/preserve `provider=codex` and route metadata when a worker result exists

### CMP-009 — Orchestration Engine

Legacy behavior:
- `mock`, `manual`, `codex-cli` branches remain semantically unchanged.

New modes:
- build all tasks/packages through existing planner and packaging.
- apply Provider Router only to `runnable` tasks.
- pending/approval-gated tasks remain pending/manual according to existing safety path.
- provider failures are accumulated as failed worker states; no uncaught Provider exception leaves the execution loop.
- collection/fan-in happens through existing result files.

Execution ordering for Phase 1:
- preserve existing Codex sequential semantics.
- NVIDIA read-only reasoning tasks may run in a bounded thread pool only after their sanitized request context has been materialized from the same pre-execution task package; Codex state-changing tasks remain sequential.
- if safe pre-materialization cannot be guaranteed by the implementation, execute new-provider tasks sequentially rather than introducing concurrent source-read/write races.

### CMP-010 — Result Normalizer

Add optional fields without changing `SCHEMA_VERSION`:

- `provider`
- `model`
- `route_reason`
- `provider_status`
- `provider_attempts`
- `provider_error_class`

Existing required/observed fields remain unchanged. `thread_id` remains the task trace identifier satisfying REQ-011's task-equivalent trace.

# ID-09 Data / Control / State Flow

## Data Flow

1. Approved plan and runtime contract are loaded through current contract loader.
2. Task Router creates TaskSlice and adds conservative `required_capabilities`; explicitly selected context files populate `input_files`.
3. Fan-out package persists TaskSlice using existing serialization.
4. For legacy modes, current execution path is used unchanged.
5. For `nvidia`/`hybrid`, Provider Router reads only mode + capabilities and returns a route decision.
6. NVIDIA route passes task prompt + input files through Context Sanitizer.
7. Sanitizer produces bounded sanitized context or a fail-closed rejection.
8. NVIDIA Adapter sends only sanitized context and config-required model metadata.
9. Adapter returns safe success/failure payload.
10. Provider Executor writes the same result/handoff artifact pattern used by the existing worker flow.
11. Result Normalizer produces worker v1 including optional provider metadata.
12. Result Collector and Fan-in consume common result data without Provider branching.
13. Stage Gate evaluates FanInReport as today.

## Control Flow

### Legacy modes

- `mock` → unchanged local worker path
- `manual` → unchanged manual artifact path
- `codex-cli` → unchanged Codex path including manual fallback

### NVIDIA mode

- safe read-only reasoning → sanitize → NVIDIA → normalize
- state-changing/unknown → explicit `routing_rejected` / failed task result; no NVIDIA call, no Codex auto fallback

### Hybrid mode

- safe read-only reasoning → sanitize → NVIDIA → normalize
- state-changing/unknown → existing Codex adapter → normalize/manual fallback if Codex fails

### NVIDIA Failure Isolation

`Provider call`  
→ classify error  
→ transient? bounded retry  
→ retry budget exhausted/non-retryable  
→ normalized `provider_failed`  
→ continue independent tasks  
→ Collection/Fan-in reports failure  
→ Gate cannot pass until recovery/remediation.

## State Transitions

| Current State | Event | Next State | Failure State |
|---|---|---|---|
| `pending` | safe hybrid route decision | `provider_selected:nvidia` | `routing_rejected` |
| `pending` | state-changing hybrid route decision | `provider_selected:codex` | `routing_rejected` |
| `provider_selected:nvidia` | sanitization pass | `provider_running` | `provider_failed:context_security_rejected` |
| `provider_running` | valid response | `completed` | `provider_failed` |
| `provider_running` | transient failure, budget remains | `retrying` | N/A |
| `retrying` | retry succeeds | `completed` | `provider_failed` |
| `provider_selected:codex` | Codex success | `completed` | existing `manual_fallback` |
| any worker completed/failed | collect/fan-in | `fanin_ready` or `fanin_blocked` | `fanin_blocked` |

No new global Provider-specific Stage Gate state is introduced.

# EC-07 SECURITY

# ID-14 Security Design

## Security Design Rules

| ID | Approved SEC Requirement | Security Design Rule | Related Task | Validation |
|---|---|---|---|---|
| SEC-D-001 | SEC-001 | Read `NVIDIA_API_KEY` from process environment at request time only; never persist/default/echo it. | TASK-005 | TEST-005, TEST-008 |

## Security Constraints to Preserve

- Hosted Provider is external/untrusted with respect to repository secret boundary.
- Model output is untrusted data and is never executed as a command/tool call in NVIDIA path.
- Capability routing is fail-safe: uncertainty never enables NVIDIA.
- Source file path must resolve under project root and not be a symlink.
- Credential filenames/content are blocked/redacted before network I/O.

## Prohibited Security Changes

- storing API keys in `.env` committed config, JSON/YAML/TOML source, test snapshots, logs or result artifacts
- enabling NVIDIA host write/shell/test/git
- sending entire repository or automatically discovered files
- logging raw Provider request/response bodies in general logs
- weakening forbidden-path/secret policy to make a smoke test pass
- adding unrelated authentication/security scope
